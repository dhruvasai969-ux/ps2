System Architecture

Four layers.
One decision.

Every incoming order passes through four tightly coupled modules before an agent is assigned. Each module contributes to the final dispatch score.

📥

Order Ingestion & Triage

New orders arrive as a stream of events. Each order is parsed, deduplicated, and immediately categorized by priority level. SLA deadlines are computed based on prep time and location distance.

priority queue SLA estimation real-time
🗺️

Distance & ETA Engine

A weighted graph models the delivery grid. Dijkstra's algorithm computes shortest paths from each eligible agent to each order's pickup location, factoring in real-time dynamic delays.

dijkstra dynamic delays ETA prediction
⚖️

Multi-Factor Scoring

Each agent–order pair is scored across five dimensions: travel time, load balance, agent rating, SLA urgency, and priority weight. The highest-scoring eligible agent wins the assignment.

heuristic scoring weighted sum fairness
🔁

Feedback & Rebalancing

As agents complete deliveries, the system recalculates load metrics and triggers re-assignment checks. Overloaded agents are protected; idle agents are prioritized in future rounds.

event-driven load balancing adaptive

Decision Logic

How the Scoring Works

Each potential agent–order pair receives a composite score. The assignment goes to the agent with the highest score, subject to capacity constraints.

Step 1 — Eligibility Filter

Only agents with fewer than 2 active orders and marked as "available" enter the pool. This enforces the hard capacity constraint before any scoring happens.

eligible = [a for a in agents if a.load < 2 and a.available]

Step 2 — ETA Calculation

For each eligible agent, compute estimated time to reach the restaurant (travel) plus restaurant prep time. Uses shortest-path distance on the weighted delivery grid.

ETA = travel_time(agent.loc → order.loc) + order.prep_time

Step 3 — Multi-Factor Score

The dispatch score balances five weighted factors. Weights are tunable. Priority multiplier amplifies the score for urgent orders, pushing them ahead in the queue.

Score = w₁·(1/ETA) + w₂·(1−load) + w₃·rating + w₄·sla_urgency + w₅·priority

Step 4 — Assign & Update State

The highest-scoring agent is assigned. Their load counter increments. Order status changes to "assigned." If no agent is eligible, the order enters a retry queue with escalating priority.

best = max(eligible, key=lambda a: score(a, order))

Design Decisions

Trade-offs & Reasoning

Why we chose a heuristic scoring model over pure optimization — and what we gain and give up.

Heuristic Scoring

Our chosen approach: weighted multi-factor score per agent–order pair.

Sub-200ms decision time, scales to 1000+ orders/min
Interpretable — easy to tune weights per business need
Handles streaming inputs naturally
Not globally optimal — myopic, local decisions
Weight tuning requires domain knowledge

ILP / Global Optimization

Alternative: integer linear programming for globally optimal assignment.

Provably optimal for a batch snapshot
Handles complex multi-constraint problems
Latency: 2–30 seconds for real problems
Cannot handle continuous order streams easily
Black-box — hard to debug and justify

Reinforcement Learning

Alternative: train an RL agent to learn dispatch policy from experience.

Can discover non-obvious patterns over time
Self-improving with more data
Requires extensive training data and infra
Unstable in non-stationary environments
Overkill for hackathon scope and scale
